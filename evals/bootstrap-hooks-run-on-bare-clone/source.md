出典: 2026-11-01 のオーナーの指摘 (この事例を追加した PR)。bootstrap 済みのリポジトリで観測した。レビューゲートの本体が TypeScript で書かれ、git hook (pre-commit / pre-push) が作業環境の Node 22 で実行していた (根拠は「ai-box と devcontainer が既に Node 22 を持つ」)。Claude Code の PreToolUse hook はすべての Bash とすべての Edit / Write にマッチし、入力の解析に `node` を使い、解析できなければ「推測しない」として止めていた。迂回の検出にはシェルの字句解析器を自作していた。そのため Node のないホストでは commit / push ができず、ホストの Claude Code は Bash もファイル編集も使えなかった。docker があっても、`frontend/` に触れる commit はテキストの修正でも「frontend dependencies are missing; run '../dev pnpm install' ...」で止まっていた (triary `.githooks/lib.sh` の `require_frontend_deps`)。オーナーの指摘は「ai-box は私が AI 開発をするための環境で、clone した人がその上で動いている前提にされては困る」「開発コンテナを立ち上げないと git push すらできない、ホストで動作確認を手伝ってもらう Claude が何もできない、のは本末転倒」。補足: 「docker やコンテナ環境があるところで push できるなら大丈夫。clone した後にあれも必要これも必要となって、ちょっとテキストを変えて、チェックは CI に投げようと動作確認なしで push しようとしたときに妨害されるのが問題」
