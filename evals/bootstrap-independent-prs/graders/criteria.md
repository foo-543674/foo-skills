AI の応答を読み、次をすべて満たせば合格:

- 中身が依存しない作業 (依存の更新等) は base ブランチ (main 等) から切る設計になっている。中身の依存と関係なく、直前の PR のブランチから続けて切って積んでいたら不合格
- ログイン画面のように中身が未マージの PR に依存する作業は、依存を断てないか検討したうえで、断てなければ #12 の上に積んで PR を出してよい。依存先のマージまで作業をローカルにだけ溜めて PR を出さない設計なら不合格
- 積んだ PR は、その PR の分だけの差分が見え、何に依存しどこを見てほしいかが説明にある。下の PR のマージ後の付け替えやマージの順序を AI が持つ
- 人間への承認依頼が、その時点で単独で判断できる PR だけになっている。「#12 のマージ後に承認してください」「◯ 日後に承認してください」のような順序・時間の条件付きの依頼を人間に渡していたら不合格
- 公開からの期間の待ちを、人間の記憶ではなく仕組み (依存更新ツールの待機の設定、検証器による経過日数の確認、条件を満たしてから PR を出す等) が持つ
- 承認依頼で、その PR の差分のうち人間に見てほしい箇所を示す
