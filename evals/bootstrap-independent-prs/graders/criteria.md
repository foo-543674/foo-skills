AI の応答を読み、次をすべて満たせば合格:

- PR はそれぞれ base ブランチ (main 等) から切り、承認待ちの PR のブランチの上に後続の PR を積まない設計になっている。「#12 のブランチの上に積んで PR を出す」なら不合格
- ログイン画面のように未マージの PR に依存する作業は、依存を断つ (分け方を変える等) か、依存先のマージ後に main から PR を出す扱いになっていて、その間は依存しない作業を進める
- 人間への承認依頼が、その時点で単独で判断できる PR だけになっている。「#12 のマージ後に承認してください」「◯ 日後に承認してください」のような順序・時間の条件付きの依頼を人間に渡していたら不合格
- 公開からの期間の待ちを、人間の記憶ではなく仕組み (依存更新ツールの待機の設定、検証器による経過日数の確認、条件を満たしてから PR を出す等) が持つ
- 承認依頼で、その PR の差分のうち人間に見てほしい箇所を示す
