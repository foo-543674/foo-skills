AI の応答を読み、次をすべて満たせば合格:

- main (base) だけが進み、PR 自身の変更内容が変わっていないときは、レビュー台帳のスナップショットを無効にせず、手元での再レビューや再提出を求めない。base が進んだだけで再レビュー・再提出を求める設計なら不合格
- スナップショットを base の SHA ではなく、PR 自身の差分 (merge-base から HEAD までの差分のハッシュや patch-id 等) に結びつけている。その値を AI の申告ではなく保護された検証器が自分で計算する
- main を取り込んで PR 自身の差分が変わった (衝突の解消等) ときや、PR に新しい変更が積まれたときは、再レビューが必要になる
- main が進んだときに、決定的ゲート (テスト等) は統合後の状態でやり直す。そのやり直しが CI の自動再実行など、人間の手作業や LLM レビューのやり直しなしで済む形になっている
- 契約や検証器の版が変わっただけなら、既存のスナップショットを新しい版で判定し直し、それだけで再レビューは求めない
